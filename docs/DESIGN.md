# ORMA — Design Direction

## Concept

ORMA deve sembrare un vero spazio fisico scout trasformato in esperienza digitale.

La metafora principale è:

> "Il mio tavolo."

Non una dashboard che imita un tavolo.

Il tavolo è realmente la struttura visiva della Home.

---

# Visual language

## Realismo

Il risultato deve essere fotorealistico o molto vicino alla fotografia.

Preferire:

- materiali fisicamente credibili;
- luce naturale;
- ombre realistiche;
- imperfezioni;
- texture;
- carta;
- legno;
- tessuto;
- metallo.

Evitare:

- estetica cartoon;
- plasticosa;
- fantasy;
- videogame;
- "AI aesthetic".

---

# Asset

Quando possibile utilizzare asset reali o ufficiali.

Per:

- Specialità;
- Competenze;
- Tappe;
- documenti ufficiali;

utilizzare i materiali ufficiali disponibili e autorizzati.

Le carte disponibili in PDF devono essere mantenute come fonte originale.

Gli asset web possono essere generati a partire dal PDF.

---

# 3D

Il 3D deve essere usato per:

- tavolo;
- carte;
- oggetti ambientali;
- illuminazione;
- profondità;
- movimento della camera.

Non usare il 3D solo per dimostrare che il progetto utilizza Three.js.

---

# Interazioni

Le interazioni devono essere:

- morbide;
- fisiche;
- brevi;
- prevedibili.

Una carta può:

- sollevarsi;
- ruotare;
- avvicinarsi;
- aprirsi.

Il movimento deve sembrare fisicamente plausibile.

---

# Modal

Quando viene aperto un contenuto:

- mantenere il tavolo visibile;
- sfocare lo sfondo;
- ridurre leggermente la luminosità;
- portare il contenuto in primo piano.

Non utilizzare il classico modal generico se una soluzione fisica è più coerente.

---

# Animazioni

Le animazioni devono essere:

- fluide;
- naturali;
- non eccessive.

Evitare:

- bounce esagerati;
- transizioni troppo lunghe;
- effetti gratuiti;
- animazioni continue.

---

# UI

La UI tradizionale deve essere minima.

Utilizzare elementi classici quando migliorano chiaramente:

- leggibilità;
- accessibilità;
- navigazione;
- modifica dati.

La UI non deve competere con la scena.

---

# Colori

La palette deve derivare principalmente dai materiali reali:

- legno;
- carta;
- tessuto;
- metallo;
- elementi scout.

Non definire una palette artificiale prima di avere stabilito l'aspetto del tavolo.

---

# Tipografia

La tipografia deve essere molto leggibile.

Può avere un carattere editoriale/analogico per titoli e contenuti, mantenendo però una sans-serif molto leggibile per informazioni funzionali.

Non utilizzare font eccessivamente "scout".

---

# Responsive

Desktop e tablet sono il riferimento principale per la scena del tavolo.

Mobile deve avere una composizione adattata, non semplicemente una versione rimpicciolita.

---

# Regola principale

> Realismo prima del tecnicismo.

Se un effetto 3D rende l'esperienza più reale, usarlo.

Se un effetto 3D esiste solamente perché "possiamo farlo", non usarlo.
